# SPY CLUB — Accessory Roll / Floating HUD

Проект извлечён из двух предоставленных Place, без замены сцены матча сценой лобби.
Исходные файлы сохранены в `places/original/`, редактируемые Luau — в `src/lobby/`
и `src/match/`. Готовые Place собираются в `dist/`.

## Скачать готовые Place

- [Лобби V128 — скачать .rbxl](https://github.com/qwertty111d-svg/spyclub/raw/refs/heads/main/dist/SPY_CLUB_LOBBY_V128_ROLL.rbxl)
- [Матч V89 — скачать .rbxl](https://github.com/qwertty111d-svg/spyclub/raw/refs/heads/main/dist/SPY_CLUB_MATCH_V89_ROLL.rbxl)

Откройте скачанные файлы через File → Open from File в Roblox Studio.
Studio Play Test в облаке не запускался; перед публикацией игры выполните
проверки из `docs/StudioValidation.md`.

## Настройка и сборка в облаке

Каждая облачная задача уже изолирована. Используйте существующий checkout
`/workspace/spyclub`; новый Git worktree не требуется.

```bash
cd /workspace/spyclub
bash tools/setup_environment.sh
export PATH="/workspace/.spy-tools/rbxl-python/bin:/workspace/.spy-tools/bin:$PATH"
python3 tools/validate.py
python3 tools/build_places.py
python3 tools/test_rbxl_tool.py
```

`tools/setup_environment.sh` устанавливает официальный Luau 0.742 из закреплённого
коммита с проверкой Git, включает компилятор и CLI. Для обработки `.rbxl`
используется `zstandard` 0.25.0. Подробные результаты находятся в `reports/`.
Дополнительные серверы и секреты для сборки не нужны. Roblox Studio в этой Linux
среде отсутствует: облачная компиляция и тесты модулей не заменяют Play Test.

## Архитектура

- `AccessoryRollConfig`: стартовые награды, категории и веса редкостей; отдельные
  веса и `styleGroup` можно задать каждой категории.
- `AccessoryRollRules`: допустимость предметов, нормализация вероятностей и
  идентификаторы повторных запросов.
- `AccessoryRollService`: серверный `Random.new()`, подготовка и проверка
  носимых моделей, защита от спама, обменов и повторной выдачи.
- `Profiles → Economy.transaction`: существующее хранилище
  `SpyClubProfiles_v1`, атомарное списание одного Roll, выдача копии предмета
  и принудительная экипировка одного слота.
- `AccessoryRollUI`, `FloatingUIController`, расширение `Preview3D`: личный
  персонаж, вращение, категории, реальные шансы и плавный HUD.
- `World`, `WorldSpec`, `WorldBootstrap`, `LobbyLighting`: входная зона и свет
  только лобби; оформление матча сохраняется.

Баланс `rolls` хранится в том же профиле, что монеты и инвентарь. Начальные
настройки: 5 новому игроку, 1 за полноценный завершённый матч, ещё 1 за победу,
2 за ежедневную награду. Покупка Rolls за Robux не добавлена.

Идентификатор запроса содержит следующий сохранённый порядковый номер и GUID.
Успешный номер сохраняется; старый запрос не может повторно списать валюту даже
после удаления его подробного квитка из ограниченного журнала. Клиент передаёт
только категорию и идентификатор; результат выбирается сервером до повторяемого
вызова DataStore. Ошибка подготовки модели или сохранения не даёт клиенту ложного
подтверждения успешного Roll.

## Миграция и совместимость

Старые предметы, количества, монеты, коллекции и экипировка сохраняются.
Неиспользованные бесплатные кейсы преобразуются один раз в Rolls по курсу 1:1;
старые записи остаются в `legacyFreeCases` для аудита. Старые ежедневные награды
кейсами заменяются Rolls. Владелец `case_luck_2x` получает лучший из двух бросков
за один Roll, с сохранением существующей проверки ограничений пользователя.
В меню вероятностей показывается влияние этого преимущества.
Два прежних неносимых предмета, доступных только из кейсов, переведены в обычную
покупку за монеты: `obsidian_frame` — 1980, `velvet_patron` — 900. Их оценка для
продажи, владение и слоты остаются прежними; в пул аксессуаров они не входят.

Промокоды и события задаются в `AccessoryRollConfig.PromoCodes` и `.Events` как
`ID = {rolls=2, startsAt=..., endsAt=..., achievement=...}`. Даты и достижение
необязательны; активных кодов по умолчанию нет. Серверный контроллер события
вызывает `rollService:award(player, "event", "ID")`; код можно погасить через
существующий `EconomyAction` с действием `rollPromo` и ID. Сумма берётся только
из конфигурации, выдача фиксируется один раз в `rollAwards`.

Общие изменённые модули синхронизируются между двумя Place. Специфичные
`Cosmetics`, `CharacterService`, `Monetization`, оформление матча и модули
расследований `CaseFiles` / `CaseDeskUI` / `CaseRound` сохраняются.
Матчевые награды остаются в существующей транзакции и механизме восстановления.

## Визуальные изменения

Компактная тёмная полупрозрачная панель: личный персонаж слева, категории,
баланс Rolls, результат, редкость и шансы справа. Параллакс сглаживается
независимо от FPS, ограничивается краями экрана и приостанавливается при вращении
персонажа. На touch-устройствах отслеживание мыши отключено. Короткая анимация
Roll заменяет длительное раскрытие кейса.

Вход клуба получает каменную площадку, козырёк, латунные детали, табличку,
тёплый свет для лиц и прохладный свет порога. Декорации не создают новых
препятствий; существующая дверь и её взаимодействия используются повторно.
Новые лампы разрешены точными правилами аудита освещения.
Входная зона и UI создаются при запуске игры; в режиме редактирования Studio
до Play исходная статическая карта не заменяется.

## Интеграция и проверка в Roblox Studio

1. Откройте `dist/SPY_CLUB_LOBBY_V128_ROLL.rbxl` и
   `dist/SPY_CLUB_MATCH_V89_ROLL.rbxl` в Studio как две сцены того же Experience.
2. Проверьте существующие настройки Place IDs и переходов. Не создавайте новую
   независимую игру или новое имя DataStore для этих файлов.
3. Выполните [план проверки](docs/StudioValidation.md). Перед публикацией
   обязательно проверьте загрузку Place, персонажа, профилей и настоящий матч.
4. После проверки опубликуйте оба Place согласованно. Сохранение черновика
   облачной среды не публикует игру Roblox.

Файлы собраны и проверяются структурно; Play Test, визуальный результат,
DataStore в Roblox, сетевые переходы и тесты устройств требуют Studio.
Точный список изменений и результаты облачных проверок: `reports/CHANGELOG.md`.
