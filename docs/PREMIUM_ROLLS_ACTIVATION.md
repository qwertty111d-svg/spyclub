# Активация покупки Rolls

В сборке V133/V94 три продукта из вашего Creator Dashboard уже подключены
в обеих копиях `RollShopConfig`. Начисления проходят через серверные квитанции.
Product ID — публичный номер продукта Roblox; API-ключи и секреты для этой
конфигурации не нужны. Публикация мест и создание продуктов выполняются отдельно.

## Подключённые Developer Products

Продукты и цены предоставлены скриншотом Creator Dashboard:

| Ключ в конфигурации | Product ID | Выдача | Цена на скриншоте |
| --- | --- | --- | --- |
| `rolls_1` | `3718610025` | 1 Roll | 99 Robux |
| `rolls_3` | `3718610195` | 3 Rolls | 279 Robux |
| `rolls_5` | `3718610306` | 5 Rolls | 449 Robux |

У каждого пакета свой ID из того же Experience. Прежние платные
IDs в `MonetizationConfig.LegacyProducts` сохраняют прежнюю выдачу. Game Pass ID
и номер каталожного предмета не заменяют Developer Product ID.

После подключения сохранить количество Rolls у каждого ID неизменным:
Roblox может повторно доставить старую квитанцию на другом сервере или в другом
месте. Для нового количества создать другой продукт.

## Подключить одинаковые IDs в обеих сценах

Таблица `Packs` уже заполнена одинаково в двух файлах:

- [Лобби: RollShopConfig](../src/lobby/ReplicatedStorage/SpyShared/RollShopConfig.luau)
- [Матч: RollShopConfig](../src/match/ReplicatedStorage/SpyShared/RollShopConfig.luau)

В Roblox Studio это ModuleScript `ReplicatedStorage/SpyShared/RollShopConfig`
каждого места. При последующих обновлениях сохраняйте ключи, IDs и
количества `1 / 3 / 5`. Оба места должны иметь одинаковую таблицу.
`MonetizationConfig` автоматически строит новые определения из неё; прежние
`LegacyProducts`, passes и существующий DataStore менять не требуется.

Цена задаётся в Creator Dashboard. `previewPrice` — предварительная подпись
для неподключённого продукта, она не определяет списание Robux. После подключения
магазин получает цену Marketplace, а окончательную сумму показывает окно оплаты
Roblox. Изменение цены и региональные настройки нужно проверять в этом окне.

## Проверить и опубликовать

После подключения IDs выполнить обычные облачные проверки:

```bash
cd /workspace/spyclub
export PATH="/workspace/.spy-tools/rbxl-python/bin:/workspace/.spy-tools/bin:$PATH"
python3 tools/validate.py
```

После настройки проверить совпадение обеих таблиц, доступность продуктов и их
цен в опубликованной тестовой версии этого же Experience. Если для проверки
создан отдельный Experience, создать его продукты отдельно и использовать его
IDs; перед production-публикацией подключить IDs продуктов production Experience
в обеих сценах. Проверить native prompt, отмену,
сохранение выдачи ровно один раз, повтор/задержку квитанции и переход между местами
по [чек-листу Studio](StudioValidation.md). Обычный Studio Play использует
временные профили и не подтверждает работу живого DataStore, оплаты или переходов.

При работе из исходников пересобрать оба файла командой `python3 tools/build_places.py`.
Публиковать лобби и матч согласованно в прежние Place IDs с настройками существующего
Experience. После публикации перезапустить старые серверы через средства Roblox,
чтобы новые покупки не попадали на сервер без новых определений продуктов.

Статус Managed pricing: Disabled означает отключённое автоматическое
ценообразование, а не запрет покупки. Доступность и цену каждого продукта
сервер получает из Marketplace; живой запрос в облаке не выполнялся.
